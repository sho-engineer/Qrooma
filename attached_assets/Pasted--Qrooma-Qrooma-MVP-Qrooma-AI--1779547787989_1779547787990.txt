あなたはQroomaのシニアフルスタックエンジニアです。
既存実装を壊さず、現在のQrooma MVPに以下の機能を追加・整理してください。

目的：
Qroomaを「複数AIが議論するツール」ではなく、
AIソロプレナー / 一人Founder / Product-minded builder / スタートアップの意思決定者が、
曖昧なテーマを比較・反証し、Decision Memo / Task List / Handoff Promptとして実行に渡せるAI Decision Roomにする。

重要：
- UI上ではモデル名やSide A/B/Cを前面に出さない
- Builder / Breaker / Operator の役割名で表示する
- チーム共同編集や共有リンクは初版では実装しない
- 実装はMVPとして軽量にする
- 既存のログイン、Room、生成処理、Free制限、コピー機能がある場合は壊さない
- 既存DB構造を確認し、必要なmigrationを安全に追加する
- raw errorをユーザーに表示しない
- 日本語UIを優先する

====================================
1. Project機能を追加
====================================

Qroomaの構造を以下に変更する。

Project
  └ Decision Room
      └ Messages / AI Discussion / Decision Memo

実装する機能：
- Project作成
- Project名変更
- Projectアーカイブ
- Project内のDecision Room一覧
- 新規Decision Room作成時にProjectへ紐付け
- 既存Roomがある場合は、Default Projectを作成して紐付ける

Projectに持たせる情報：
- id
- user_id
- name
- description nullable
- status: active / archived
- created_at
- updated_at

Room側に追加する情報：
- project_id
- decision_type
- use_project_context boolean default true

初版では実装しない：
- メンバー招待
- 権限管理
- コメント
- 共有リンク
- Project全体の自動要約
- Project横断RAG
- Future Consideration一覧
- ロードマップ自動生成

====================================
2. 同一Project内の過去Decision Memo参照
====================================

新しいDecision Roomを作成・実行するとき、同一Project内の過去Decision Memoを参照できるようにする。

仕様：
- Room作成時に「同じProject内の過去Decision Memoを参照する」ON/OFFを表示
- 初期値はON
- 参照するのはチャット全文ではなく、過去のDecision Memo中心
- 参照対象は最大3〜5件程度に制限
- 新しい順、または関連性が高い順で取得
- AI生成プロンプトにProject contextとして渡す

参照する情報：
- Project名
- Project説明
- 過去Decision Memoのタイトル
- 決定事項
- 今やる
- 今回やらない
- 後で検討
- 追加確認が必要
- 次アクション

AIが過去Decision Memoを参照した場合、最終出力カードに以下を表示する。

参照したDecision Memo
- xxx
- yyy

初版ではやらない：
- 過去チャット全文参照
- 全メッセージRAG
- ベクトル検索
- Project横断参照

====================================
3. Decision Type選択を追加
====================================

Prompt Mode / Decision Room作成時にDecision Typeを選択できるようにする。

選択肢：
- MVPスコープ
- 新機能優先順位
- LP / 訴求
- 実装方針
- 価格 / プラン
- その他

仕様：
- 必須ではなく任意
- 未選択なら「その他」として扱う
- Decision Typeに応じて、既存の比較軸テンプレートがある場合は初期表示する
- 選択肢は増やしすぎない

====================================
4. Scope分類を最終出力に追加
====================================

最終結論には必ず以下の4分類を入れる。

- 今やる
- 今回やらない
- 後で検討
- 追加確認が必要

各項目には短い理由を付ける。

例：
今やる
- Decision Type選択を入れる
  理由：何を決めるRoomかを最初に明確にできるため

今回やらない
- 共有リンク
  理由：初版ではコピー共有で代替できるため

後で検討
- Startup Mode
  理由：チーム利用ニーズが見えた段階で拡張するため

追加確認が必要
- Build Promptの利用頻度
  理由：実装AIへの引き継ぎ需要を検証する必要があるため

====================================
5. One-page Decision Memoカードを追加
====================================

最終結論は、通常の長文回答ではなく、1枚のDecision Memoカードとして表示する。

Decision Memo Cardに表示する項目：
- 決定事項
- 背景
- 判断理由
- 比較軸ごとの評価
- 判断が変わる条件
- 今やる
- 今回やらない
- 後で検討
- 追加確認が必要
- 次アクション
- 参照したDecision Memo

重要：
- 1枚のカードとして表示する
- 項目ごとの複数カード化はしない
- 編集機能は入れない
- コメント機能は入れない
- 共有リンクは入れない
- コピー機能だけ入れる

6. 比較軸ベースの判断理由を追加
====================================

Decision Memoカード内に「比較軸ごとの評価」を表示する。

初版で入れる：
- 採用案
- 主な判断理由
- 比較軸ごとの評価
- 判断が変わる条件

初版では入れない：
- レーダーチャート
- 点数評価
- 複雑なスコアリング
- 比較ダッシュボード

表示例：
比較軸ごとの評価

実装コスト：低い
理由：既存UIに選択項目を追加するだけで実装できるため

ユーザー理解：高い
理由：何を決めるRoomかが明確になるため

Qroomaらしさ：高い
理由：通常チャットではなく意思決定ツールとして見えやすくなるため

判断が変わる条件：
- 入力項目が増えて初回利用の離脱が増える場合は、任意表示にする

8. Handoffコピーを4種類実装
====================================

Decision Memoカードから以下の4種類をコピーできるようにする。

1. Decision Memoコピー
2. Task Listコピー
3. Generic AI Promptコピー
4. Build Promptコピー

仕様：
- Markdown形式でコピー
- 日本語UIなら日本語でコピー
- 英語UIが既にある場合は英語にも対応
- コピー成功時はトースト表示

Decision Memoコピー内容：
# Decision Memo

## 決定事項
...

## 背景
...

## 判断理由
...

## 比較軸ごとの評価
...

## 判断が変わる条件
...

## 今やる
...

## 今回やらない
...

## 後で検討
...

## 追加確認が必要
...

## 次アクション
...

Task Listコピー内容：
# Task List

## Task 1
- タスク名:
- 目的:
- 期待アウトプット:
- 優先度:
- 人間確認の要否:

Generic AI Promptコピー内容：
以下のDecision Memoを前提に、次に進めるための具体案を作成してください。

目的：
- この判断を実行可能な計画に落とし込むこと

前提：
[Decision Memo]

依頼内容：
- 次に取るべきアクションを具体化してください
- 不足している前提があれば質問してください
- 実行順序を整理してください
- リスクや確認事項があれば整理してください

Build Promptコピー内容：
以下のDecision MemoとTask Listをもとに、実装タスクとして整理してください。

目的：
- 決定済みの内容を、開発実装に落とし込むこと

前提：
[Decision Memo]

実装対象：
[Task List]

依頼内容：
- 必要な画面変更を整理してください
- 必要なDB / API / UI変更を洗い出してください
- 実装ステップを小さく分解してください
- 既存機能を壊さないように注意点を出してください
- 実装後の確認項目を出してください

初版では入れない：
- Manus専用コピー
- Notion専用コピー
- Linear専用コピー
- Jira専用コピー
- PDF出力
- API連携

10. 空状態 / エラー / 制限到達時UX
====================================

初版で以下を実装する。

空状態：
まだDecision Roomがありません

曖昧なアイデアや迷っている判断を、Qroomaで整理しましょう。

例：
- MVPに入れる機能を決めたい
- LPの訴求を比較したい
- 価格プランを整理したい
- 実装方針を決めたい

[新しいDecision Roomを作る]

エラー：
生成に失敗しました

一時的にAIの応答に失敗した可能性があります。
少し時間を置いて、もう一度お試しください。

[再実行する]

利用制限到達：
本日の利用上限に達しました

Freeプランでは、1日5回までDecision Roomを実行できます。
明日またお試しください。

月上限：
今月の利用上限に達しました

Freeプランでは、月100回まで利用できます。
来月また利用するか、今後提供予定のProプランをご検討ください。

必須：
- raw errorをユーザーに出さない
- 裏側ではログを残す
- 再実行ボタンを出す

初版では入れない：
- 詳細なエラーコード表示
- 問い合わせフォーム連携
- 自動復旧処理
- メール通知
- 課金アップグレード本実装

====================================

- Future Considerationに再検討条件が表示される

- 完了時にアプリ内通知が出る
- タブタイトルが生成中/完了で変わる
- 空状態が自然に表示される
- エラー時にraw errorが出ない
- Free制限到達時に自然な案内が出る
