2. テスト用ログインの緩い設定を修正
==================================================

現在、開発・テスト用に以下のような処理が残っている場合は、本番UIでは無効化してください。

確認対象：
- 未ログインでもアプリ画面に入れる
- localStorageだけでログイン済み扱いにしている
- mock userを常に返している
- devUser / testUser を自動セットしている
- auth checkをスキップしている
- protected routeが実質的に保護されていない
- Supabase sessionがなくても固定user_idで動く
- Admin判定が誰でもtrueになる

対応方針：
- 未ログインの場合は /login にリダイレクト
- /app /projects /rooms /settings /admin はログイン必須
- LP、利用規約、プライバシーポリシー、ログインページは未ログインでも表示可能
- 開発用bypassが必要な場合は環境変数で制御する
- productionではdev auth / mock login / bypass loginを必ず無効にする

例：
- ENABLE_DEV_AUTH=true の時だけ開発用ログインを許可
- production環境では常にfalse扱い
- UI上にdev loginボタンを表示しない

3. Protected Routesを整理
==================================================

以下のページはログイン必須にしてください。

- /app
- /projects
- /rooms
- /settings

未ログイン時：

Adminページ：

- Admin判定はフロントだけでなく、server action / API 側でも確認する

==================================================
4. Googleログインを実装
==================================================

ログイン画面にGoogleログインを追加してください。

ボタン文言：
Googleでログイン

仕様：
- Supabase Authを使っている場合は supabase.auth.signInWithOAuth({ provider: 'google' }) を使う
- OAuth callback後、アプリ本体に戻す
- redirectTo がある場合は元ページへ戻す
- redirectTo がない場合は /projects に遷移
- Googleログイン後、profilesテーブルにユーザー情報がなければ作成する
- 既存ユーザーの場合は既存profileを利用する
- 既存のメールログインがある場合は壊さない

保存するユーザー情報：
- user_id
- email
- display_name nullable
- avatar_url nullable
- provider: google
- role default 'user'
- plan default 'free'
- accessType default 'normal'
- isUnlimitedUser default false
- dailyRunLimit default 5
- monthlyRunLimit default 100
- created_at
- updated_at

既存profilesテーブルがある場合：
- 既存schemaを優先
- 足りないカラムがあればmigrationで追加
- 既存データを壊さない

5. Googleログインボタンのロゴ
==================================================

Googleログインボタンには、正しいGoogleロゴを使用してください。

要件：
- Googleの公式スタイルに近いマルチカラーの「G」ロゴを使用する
- 単なる黒いG、汎用アイコン、絵文字、FontAwesomeの簡易アイコンだけで代用しない
- ボタン内でロゴが潰れないようにする
- ロゴサイズは18px〜20px程度
- ボタンは白背景、薄いグレー枠、黒または濃いグレー文字を基本にする
- ダークモードがある場合も視認性を確保する
- hover / focus / disabled 状態も用意する

表示例：
[ Google Gロゴ ] Googleでログイン

実装方法：
- 公式のGoogle “G” ロゴに近いSVGをコンポーネント化して使う
- 既存のUIライブラリに公式に近いGoogleロゴコンポーネントがある場合はそれを使ってよい
- ただし見た目が公式ロゴと明らかに違う場合は使わない

注意：
- Google Client Secretをフロントに置かない
- ロゴ画像を外部URL直読み込みにして表示崩れする実装は避ける
- 可能ならローカルSVGまたはコンポーネントとして管理する

6. Adminメールアドレスを設定
==================================================

初期Adminユーザーのメールアドレスを以下に設定してください。

Admin email:
shoengineer5@gmail.com

仕様：
- このメールアドレスでログインしたユーザーはAdmin権限を持つ

- profileがまだ存在しない場合は、Googleログイン後または初回profile作成時にAdminとして作成する

- 複数指定できるようにする場合はカンマ区切り
- ハードコードする場合でも、後で環境変数に移せる形にする

Admin判定例：
- session.user.email が ADMIN_EMAILS に含まれている場合、admin扱い
- profiles.role === 'admin' の場合もadmin扱い
- 初回ログイン時にADMIN_EMAILSに含まれるemailならprofiles.roleをadminにupsertする

9. ログアウトを整理
==================================================

Settings / Account にログアウトボタンを置いてください。

ログアウト仕様：
- supabase.auth.signOut() を実行
- sessionをクリア
- /login に遷移
- ログアウト後にブラウザバックでapp画面に戻れないようにする
- 必要ならsession再確認で/loginへ戻す

==================================================
