P0-2: Fix completed-before-Firestore-save race condition
==================================================

Current issue:
RoomDetailPage starts decisionMemosService.save() asynchronously after conclusion SSE.
But run status becomes completed when done SSE arrives, without waiting for Firestore save.

This creates a race:
- user sees completed
- Firestore save may still be in-flight
- if save fails, completed already happened

Expected behavior:
Run status must become completed only after:

1. Final Decision Memo is generated.
2. Decision Memo is saved to Firestore.
3. UI can display the memo.

Please implement one of these approaches:

Preferred approach:
Add a status:
- saving_memo

Expected lifecycle:
running
→ checkpoint or checkpoint_ready
→ generating_conclusion
→ saving_memo
→ completed

If Firestore save fails:
- set status to memo_failed or memo_save_failed
- show a clear error
- do not mark completed

Implementation guidance:
- Store the Firestore save Promise when conclusion is received.
- When done SSE arrives, await the save Promise before setting completed.
- If conclusion arrives after done due to stream timing, handle gracefully.
- Do not rely on localStorage as source of truth for completed.
- localStorage may remain as cache/fallback, but Firestore save must be the completion gate.

Expected:
completed cannot happen before Firestore save succeeds.
