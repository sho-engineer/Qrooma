Replitへ

Qrooma のプロンプト周りを、以下の方針で実装してください。

今回の目的は、Qroomaを「曖昧なテーマを、比較・反証・整理し、実行に渡せる形にするアプリ」として成立させるために、Prompt Mode・内部ロール・Handoff用プロンプトを整理することです。

---

# 1. 通常モードとPrompt Modeの違いを明確化する

## 通常モード
軽く相談・壁打ちしたいときのモード。

用途:
- とりあえず相談したい
- 条件がまだ曖昧
- まず考えを整理したい
- 深い設定は面倒

## Prompt Mode
ちゃんと判断したいときのモード。

用途:
- 比較軸を決めたい
- 複数案を客観比較したい
- 反証を入れたい
- Decision Brief / Task List まで出したい
- 外部AIや実行ツールに渡せる形にしたい

UI上でも、通常モードとPrompt Modeの違いが分かるようにしてください。

---

# 2. Prompt Modeの入力項目

Prompt Modeでは、以下の入力項目を持たせてください。

## 必須項目

### 1. 検討テーマ
ユーザーが検討したい内容。

例:
- 次のMVPリリースでどの機能を優先すべきか検討したい
- QroomaのLP訴求をどうするか決めたい
- Free / Pro のプラン設計を考えたい

### 2. 最終的に決めたいこと
議論のゴール。

例:
- 次に実装する機能を1つ決めたい
- 最も良い訴求案を選びたい
- 料金プランの初期案を決めたい

### 3. 比較軸
Qroomaが推奨軸を出し、ユーザーが編集できるようにする。

---

## 任意項目

### 4. 前提・制約
例:
- 開発者は1人
- 2週間以内に出したい
- まずFreeで検証したい
- 外部API連携はまだしない

### 5. 反論の強さ
選択式:
- Soft
- Standard
- Strong

初期値は Standard。

### 6. 出力粒度
選択式:
- Quick
- Standard
- Detailed

初期値は Standard。

---

# 3. Prompt Modeテンプレート

MVPでは、以下5つのテンプレートを用意してください。

## 1. MVPスコープ決定

用途:
次のリリースで何を入れるか決める。

推奨比較軸:
- コア価値への近さ
- 実装コスト
- リリース速度
- ユーザーへの分かりやすさ
- 将来拡張性

初期値:
- 反論の強さ: Standard
- 出力粒度: Standard

---

## 2. 新機能優先順位

用途:
複数の機能候補から優先順位を決める。

推奨比較軸:
- 顧客価値
- 実装しやすさ
- 差別化
- 利用頻度
- リスク

初期値:
- 反論の強さ: Standard
- 出力粒度: Standard

---

## 3. LP / 訴求比較

用途:
サービスの打ち出し方やメッセージを決める。

推奨比較軸:
- 分かりやすさ
- 刺さりやすさ
- 差別化
- 信頼感
- CTAにつながるか

初期値:
- 反論の強さ: Standard
- 出力粒度: Standard

---

## 4. 実装方針比較

用途:
技術方針や実装方法を比較する。

推奨比較軸:
- 実装速度
- 保守性
- 複雑性
- 将来拡張性
- バグリスク

初期値:
- 反論の強さ: Standard
- 出力粒度: Standard

---

## 5. 価格 / プラン設計

用途:
Free / Pro / Connect などの料金や制限を考える。

推奨比較軸:
- 収益性
- ユーザーの納得感
- 運営コスト
- アップグレード導線
- シンプルさ

初期値:
- 反論の強さ: Standard
- 出力粒度: Standard

# 4. 比較軸の仕様

比較軸は、Qroomaの判断品質に直結するため、以下を実装してください。

## 仕様

- Qroomaがテンプレートごとに推奨軸を表示
- ユーザーがON/OFFできる
- 「その他」で自由追加できる
- 各軸に重み付けできる

## 重み付け

選択式:
- 高
- 中
- 低

英語UIの場合:
- High
- Medium
- Low

## 注意

比較軸は固定ではなく、ユーザーの判断基準を反映できるようにしてください。

# 5. 内部ロールプロンプト

シングルモデル前提で、1つのモデルが複数役割を演じる構成にしてください。

役割は以下の3つです。

- Builder
- Breaker
- Operator

日本語UIでは以下の表示にしてください。

- Builder → 提案
- Breaker → 検証
- Operator → 実行整理

英語UIでは以下の表示にしてください。

- Builder
- Breaker
- Operator

---

## Builder

### 役割
複数の実行可能な候補案を出す。  
最初から1案に閉じない。

### 主な仕事
- 候補案を複数出す
- 各候補のメリット・デメリットを整理する
- 向いている条件 / 向いていない条件を出す
- 暫定的な有力案を置く

### 出力に含める
- 候補案
- メリット
- デメリット
- 向いている条件
- 向いていない条件
- 暫定推奨

### 禁止事項
- いきなり1案に閉じる
- 最終結論まで確定する
- リスク検証を全部抱え込む
- 抽象論だけで終わる

---

## Breaker

### 役割
Builderの案を検証し、崩れる条件や弱い前提を明らかにする。

### 主な仕事
- 各案が崩れる条件を出す
- 前提依存を明らかにする
- 比較軸上の弱点を示す
- 別案が勝つ条件を示す
- 次に確認すべきことを出す

### 出力に含める
- 崩れる条件
- 比較軸上の弱点
- 前提依存
- 別案が勝つ条件
- 次の確認事項

### 禁止事項
- Builderの言い換え
- 否定のための否定
- 一般論の懸念だけ
- 新案を増やして議論を散らす
- 「ケースバイケース」で終わる

### 注意
Breakerは新しい案を大量に出す役割ではありません。  
ただし、「この条件なら別案の方がよい」という形で代替条件を示すことは許可します。

---

## Operator

### 役割
BuilderとBreakerを踏まえて、現実的な落とし所を作る。

### 主な仕事
- 第一候補を決める
- 第二候補を整理する
- 棄却候補を明確にする
- 将来検討に回すものを整理する
- 次アクションに落とす

### 出力に含める
- 採用案
- 第二候補
- 棄却案
- 採用理由
- 棄却理由
- 残論点
- 次アクション
- 将来検討

### 禁止事項
- ゼロから議論をやり直す
- 案を増やし直す
- 抽象論だけで終わる
- 全部あり、で終わる

---

# 6. 対案を出す役割

対案を出す主担当は Builder です。

## 役割ごとの整理

### Builder
候補案・対案を出す。

### Breaker
新しい案を増やすのではなく、各案が崩れる条件や、別案が勝つ条件を示す。

### Operator
候補案と反証を踏まえて、採用案・棄却案・将来検討・次アクションに整理する。

この役割分担が崩れないようにしてください。

# 7. Prompt Modeの出力方針

Prompt Modeでは、通常モードよりも構造化した出力を出してください。

出力に含めるもの:

- 候補案
- 各案のメリット
- 各案のデメリット
- 向いている条件
- 向いていない条件
- 比較軸ごとの評価
- 反証
- 採用案
- 棄却案
- 残論点
- 次アクション
- 将来検討
- Decision Brief
- Task List

ただし、画面上は重くならないように、詳細は折りたたみで表示してください。

# 8. Handoff用プロンプト

MVPでは、外部AIに渡すためのプロンプトを2種類用意してください。

## 1. Generic AI Prompt

用途:
- ChatGPT
- Claude
- Gemini
- Manus
- その他AI

に渡せる汎用プロンプト。

含めるもの:
- 背景
- 目的
- 決定事項
- 採用案
- 棄却案
- 採用理由
- 残論点
- 次アクション
- タスク
- 期待アウトプット
- 注意点

---

## 2. Build Prompt

用途:
- Claude Code
- Replit
- GitHub Copilot
- Cursor

などに渡す実装向けプロンプト。

含めるもの:
- 実装目的
- 採用仕様
- やらないこと
- 受け入れ条件
- 修正対象
- UI要件
- 注意点
- 返してほしいもの

# 10. Prompt Mode UI

Prompt Modeは、以下の流れにしてください。

1. テンプレート選択
2. 検討テーマ入力
3. 最終的に決めたいこと入力
4. 推奨比較軸の確認・編集
5. 前提・制約入力
6. 反論の強さ
7. 出力粒度
8. 開始

ただし、画面が重くならないように、

- テンプレート選択
- 必須項目
- 詳細設定

の3段階にまとめてください。

# 12. 受け入れ条件

以下を満たしたらOKです。

## Prompt Mode

- 通常モードとの違いが明確
- 検討テーマ、決定したいこと、比較軸を入力できる
- 前提・制約、反論の強さ、出力粒度を任意で設定できる
- テンプレートを選べる
- テンプレートごとに推奨比較軸が入る
- 比較軸をON/OFFできる
- その他軸を追加できる
- 高 / 中 / 低で重み付けできる

## 内部ロール

- Builderが複数案を出す
- Breakerが崩れる条件・前提依存・比較軸上の弱点を出す
- Operatorが採用 / 棄却 / 残論点 / 次アクション / 将来検討に整理する
- 3役の出力が似た内容の言い換えにならない

## Handoff Prompt

- Generic AI Promptを生成・コピーできる
- Build Promptを生成・コピーできる
- Markdown形式でコピーできる
- UI言語に合わせて日本語 / 英語で出る

## 多言語

- 日本語UIでは日本語ラベル
- 英語UIでは英語ラベル
- モデル名ではなく役割名で表示される
