方針変更です。
Supabaseは使わず、Firebase Auth + Firestore 構成に切り替えてください。

目的：
- Supabase依存を外す
- Firebase AuthenticationでGoogleログインを実装する
- Firestoreでユーザー、Project、Decision Room、Decision Memo、Feedback、Voteを管理する
- できるだけ無料枠で運用できる構成にする
- 一般ユーザーには「無料で試す」ではなくWaitlist導線を見せる
- テスター / 先行利用者だけがクーポンコード経由でログイン画面に進めるようにする
- 現在右下にあるテスト用のプラン変更UIを削除する

==================================================

- VITE_SUPABASE_URL

- SupabaseのSecretsは不要にしてください

8. クーポン認証仕様
==================================================

クーポンが正しい場合のみ、ログイン画面に遷移できるようにしてください。

推奨仕様：
- valid coupon codeをフロントエンドにハードコードしない
- 可能であればReplit側のserver APIで検証する
- 例：POST /api/early-access/validate
- 環境変数 EARLY_ACCESS_CODES に有効コードを設定できるようにする
- 例：EARLY_ACCESS_CODES=TESTER2026,FOUNDER2026,EARLYADJUDO
- 認証成功時は短期間有効なcookieまたはlocalStorage flagをセットする
- 例：early_access_granted=true
- 有効期限は7日程度
- 成功後 /login に遷移する

MVPとして簡易実装する場合：
- server APIが難しければ、まずは最小実装でもよい
- ただし、できるだけフロントに有効コードを直書きしない
- 将来的にFirestoreのearlyAccessCodes collectionで管理できる形にする

認証成功後：
- /login に遷移
- Googleログイン可能
- Googleログイン後、通常のアプリ機能を使える

認証失敗後：
- /early-access に留まる
- エラーメッセージを表示する

9. Loginページのアクセス制御
==================================================

/login は原則として以下の条件で表示してください。

表示してよい場合：
- early_access_granted がある
- すでにログイン済み
- Admin emailでのアクセスを想定する場合
- 開発環境でENABLE_DEV_AUTH=true

表示しない場合：
- 一般ユーザーが直接 /login にアクセスした
- early access認証がない
- 未ログインかつクーポン未認証

その場合：
- /waitlist または /early-access に誘導する

/login の表示内容：
- Googleでログイン
- 正しいGoogle Gロゴ
- エラー表示

ログイン後：
- users/{uid} を作成または更新
- early access経由でログインした場合は accessType = early_access
- Admin emailの場合は role = admin / isUnlimitedUser = true
- /projects に遷移

12. Firestore Security Rules
==================================================

Firestore Security Rulesを設定してください。

基本方針：
- users は本人のみ読み書き可能
- projects / rooms / messages / decisionMemos は userId === auth.uid の場合のみ読み書き可能
- feedback は必要に応じてログインユーザーが投稿可能
- feedbackVotes は必要に応じてログインユーザーが作成可能
- waitlist は未ログインでも作成可能。ただし読み取りはAdminのみ
- admin集計はAdminのみ
- 他人のprojectId / roomIdをURL直打ちしても見られないようにする

注意：
- フロント側のuserIdだけを信用しない
- Firestore rulesで必ずauth.uidと一致確認する
- Admin判定もrulesまたはサーバー側で確認する
