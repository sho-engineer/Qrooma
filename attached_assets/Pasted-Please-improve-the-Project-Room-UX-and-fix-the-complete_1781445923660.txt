Please improve the Project / Room UX and fix the “completed but no conclusion” issue.

## 1. Project / Room UX redesign

The current UX is confusing.
Right now, Project and Room feel disconnected.

I want two behaviors:

### A. Create a room directly under a project
When a user opens the left sidebar and sees a project, they should be able to add a room directly under that project.

Expected behavior:
- In the sidebar, each project should be expandable/collapsible.
- Rooms belonging to that project should appear nested under it.
- Each project should have a clear “+” or “+ New Room” action.
- Clicking it should create a room with that projectId and open the room.

Preferred structure:

Projects
- New Business
  - PR Strategy
  - Pricing Strategy
  - Launch Timeline

Do not separate “Projects” and “Rooms” as two disconnected lists if the room belongs to a project.

### B. Move an existing room into a project
For existing standalone rooms, add a clear action:
- “Move to project”
- “Remove from project” (optional)
- or “Change project”

Expected behavior:
- In the room “…” menu, add “Move to project”
- Open a modal or menu to choose:
  - Project A
  - Project B
  - No project
- After moving, update room.projectId
- The room should appear under that project in the sidebar and project detail page

## 2. Please prepare 2 UX options

Please propose and implement one of these two directions:

### Option 1 (recommended)
Project-centric nested sidebar
- Projects are the primary structure
- Rooms appear under projects as children
- Standalone rooms can be shown in a separate “Unassigned rooms” section

### Option 2
Keep project list and room list separate, but clearly show each room’s project and allow direct creation/move actions

Please tell me which one you implemented and why.
